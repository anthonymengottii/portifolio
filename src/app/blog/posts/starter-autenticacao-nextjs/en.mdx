## What’s Already in the Project

The template covers the full auth flow from a UI perspective:

- **Sign up** (`/sign-up`, `/`) — Registration form with banner and social buttons (Gmail, Github, Gitlab) as placeholders.
- **Sign in** (`/sign-in`) — Email/password with basic validation and the same social buttons.
- **Email verification** (`/email-verification`) — Screen with 6-digit code input.
- **Password reset** — Request reset (`/password-reset-request`) and set new password (`/set-new-password`), plus success confirmation screens.
- **Confirmations** — Success after login and after password reset.
- **Profile** (`/profile`) — Name and email form (persisted in localStorage for now).
- **404** — Page for unknown routes.

It’s not just “a login screen”: it’s the set of screens most products need before wiring up a real backend.

## Components and Branding

Besides the screens, the project includes reusable components: **Button**, **Checkbox**, **InputField**, and **LogoText**. **LogoText** is an SVG component that displays the word **“LOGO”** (or whatever text you set) at the top of the login and signup forms — instead of a generic icon, you get an editable text brand in `LogoText.tsx`, with color controlled via `fill`. Field icons (email, password, user, key) and social logos (Github, Google) follow the brand color defined in the config.

## Visual Config Without Touching Components

All visual customization lives in **`template.config.ts`** at the project root. A single file controls:

- **Theme** — light, dark, or system.
- **Colors** — neutrals (sand, gray, slate), **brand** (blue, indigo, violet, etc.) and **accent**.
- **Style** — borders (rounded, playful, conservative), surfaces (filled, translucent), buttons (flat, plastic), transitions and UI scaling.

The **brand** color drives primary buttons, logo, input icons and focus states. You change the template’s look without opening components — just edit the config.

## Stack and Next Steps

- **React 18+**, **Vite**, **TypeScript**, **Tailwind CSS**, **React Router**.
- Responsive layout: banner hidden on mobile, social buttons in a row.
- Suggested next steps: add **AuthProvider** + **useAuth**, private route protection, and integration with your chosen auth provider (Supabase, Clerk, Firebase or your own JWT API). Stricter validation (Zod + React Hook Form) can be wired into the existing screens.
