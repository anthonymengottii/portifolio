## Overview

**Upay** is a full payment platform in production, used by partners and merchants to process real transactions. Built with **Clean Architecture**, it lets businesses process payments independently with full control over fees, customers, transactions and reports. The stack is **TypeScript/Node.js 20+** on the backend (Express, Prisma, PostgreSQL, Redis), **React 18** on the frontend (Tailwind CSS, shadcn/ui, React Router, Chart.js/Recharts), and interactive **Swagger/OpenAPI** documentation. The project repository is at [github.com/anthonymengottii/upay_sistema](https://github.com/anthonymengottii/upay_sistema).

## Key Features

### Payments and Checkout
- **PIX, Card and Boleto**: Processing with multiple PSPs (Fyntra, Pagar.me, Citrex), configurable priority and automatic retry
- **Payment Links**: Unique slug, flexible settings, automatic stock control and Meta Pixel per link
- **Public Checkout**: Responsive UI with customizable theme (color, logo, copy)
- **Checkout Builder**: Checkout layout configurable per link — variants by category: personal data (Default, Classic, Compact, Inline), address (Default, Classic, Compact, Inline), order summary (Default, Classic, Compact, Minimal, List), payment method (Default, Classic, Tabs, List, Compact), social proof (Default, Classic, Carousel, Badges, Grid, Minimal)
- **Installments**: Up to 12x with differentiated fees; automatic release of card transactions (full amount at 30 days, installments one per 30 days)
- **Payment Split**: Automatic split between gateway and merchants (Pagar.me recipients), calculation from registered fees
- **Idempotency**: Protection against duplicate requests

### Security and Compliance
- **MFA (Google Authenticator)**: TOTP, automatic QR code, activation only after validation
- **KYC**: Document verification (individual and business), smart home screen by status, feature lock until approval
- **API Keys**: Programmatic access with rate limiting (100 req/15 min), audit logs
- **Webhooks**: Real-time notifications; Swagger docs and examples in multiple languages

### Finance and Operations
- **Financial Management**: Custom fees per method and company, reserve, PIX transfers, withdrawals, receivables anticipation
- **Stock Control**: Auto-decrement on payment, link deactivation at zero stock, digital and physical products
- **Coupon System**: Percent or fixed discount, validity, usage limits, checkout validation and rate limiting on validate API
- **Rewards (Upay Rewards)**: Tiers by revenue, progress in header, reward claiming, admin panel for tiers
- **Referral Program**: Unique code per user, configurable fixed reward and recurring commission, dashboard panel

### Infrastructure and UX
- **Cloudinary**: Image storage (products, KYC, reward tiers), automatic optimizations (WebP, cache)
- **Subdomains**: `app.[domain].com` (app) and `checkout.[domain].com` (public checkout), detection and dynamic CORS
- **Email**: Handlebars templates (.hbs), PDF receipt on payment confirmation, dark-mode prevention, test send in admin
- **Admin Panel**: Company, transaction and client management; KYC, rewards, email templates; profit reports and security dashboard

## Checkout Builder

The **Checkout Builder** lets each payment link have its own checkout layout without changing code. In the dashboard, the merchant selects variants per block: **personal data** (Default, Classic, Compact, Inline), **address** (same options), **order summary** (Default, Classic, Compact, Minimal, List), **payment method** (Default, Classic, Tabs, List, Compact), and **social proof** (Default, Classic, Carousel, Badges, Grid, Minimal). So the same product can be sold with leaner checkouts (Compact, Minimal) or fuller ones (Classic, with review carousel), depending on channel or campaign. Configuration is done when creating or editing the link, and the checkout screen reflects the chosen options.

## Technologies Used

- **Backend**: TypeScript, Node.js 20+, Express, Prisma ORM, PostgreSQL 13+, Redis 6+ (cache)
- **Frontend**: React 18, TypeScript, Tailwind CSS, shadcn/ui, React Router, Zod, Chart.js, Recharts
- **API**: REST, Swagger/OpenAPI, pagination sanitization (page/limit), strict validation
- **Architecture**: Clean Architecture (controllers by domain, services, auth/security/validation middlewares)
- **Quality**: Automated tests (40+ files), integration tests (payment, withdraw, KYC, auth), test helpers

## Challenges and Learnings

The main challenge was evolving from an API-focused gateway into a **full platform**: configurable checkout, KYC, rewards, referrals and financial management while keeping the API simple and operations stable. The approach was Clean Architecture, component variants (Checkout Builder) and integrations (Cloudinary, multiple PSPs) without blocking the payment core. Idempotency, rate limiting and strict validation reduced production errors and abuse on public endpoints (e.g. coupon validation).

## Outcome

The platform is **live in production** at [app.upaybr.com](https://app.upaybr.com/), with real transactions processed daily. It includes a dashboard for merchants, a public checkout customizable per link, official SDKs (Node, Python, PHP), API documentation and full flows for KYC, withdrawals and rewards. Swagger docs (`/api/docs`) and OpenAPI enable fast onboarding for new partners. Source code is available at [github.com/anthonymengottii/upay_sistema](https://github.com/anthonymengottii/upay_sistema).
