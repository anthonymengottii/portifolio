## About the Project

**Cardapyu** is a SaaS digital menu platform for restaurants and delivery, in the style of iFood but with **no per-order commission**. Customers order from their phone (delivery or pickup) or from the table tablet, track the order in real time, earn points and favorite dishes. The store owner manages everything in a full admin panel: menu, orders, tables, payments, staff, reports and WhatsApp. Many stores run on the same deployment, each on its own domain or subdomain, with plans, free trial and monthly billing. Live at [cardapyu.com](https://cardapyu.com).

![cardapyu.com home page in production](/images/projects/cardapyu/site-inicio.webp)

## Customer Experience

- **Menu**: categories with scroll-spy, search, highlights, "order again" and five visual themes (classic, list, compact, magazine, minimal).
- **Options and add-ons**: required/optional groups with min, max and live pricing; the server validates the choice and computes the price.
- **Checkout**: delivery with saved addresses and ZIP lookup (ViaCEP), coupons and notes.
- **Real Pix (BR Code)**: QR code and copy-paste code on the store's key; the order stays "Awaiting Pix" until the store confirms and the customer's screen updates on its own. Card on the card machine and cash with change.
- **Loyalty and coupons**: points per real spent, segmented coupons (first order, inactive customers, VIP) and a referral program.
- **WhatsApp login**: a 6-digit code sent to the customer's number, no password.
- **PWA**: installable, with an icon generated from the store logo, offline menu and direct product and category links with WhatsApp previews.

![Menu section on cardapyu.com: banners, promotions, ordering in a few taps and real-time status](/images/projects/cardapyu/site-cardapio.webp)

## 3D Dishes and Augmented Reality

On AR plans, customers open the menu from the table QR Code or the link, tap "View in 3D" and see the dish in 3D or in augmented reality, at real size, on top of the table, right in the phone's browser with no app to install. The viewer uses `model-viewer` and the models are generated through the Meshy.ai integration.

![Augmented reality section on cardapyu.com](/images/projects/cardapyu/site-realidade-aumentada.webp)

## Table Mode (tablets)

Table tablets open the menu in kiosk mode, without login, using a per-table token in the link/QR. Orders go to the kitchen and add up on the table's open tab; customers can call the waiter or ask for the bill, and staff close the tab choosing the payment method. After inactivity, the tablet returns to a welcome screen with the store's promotions.

## Admin Panel

![Overview of the system's features on cardapyu.com](/images/projects/cardapyu/site-recursos.webp)

- **Orders and kitchen (KDS)**: real-time queue filtered by status, columns per stage, wait time and sound alert.
- **Menu**: products, categories, banners, options, image cropping and a sold-out toggle (the server also rejects sold-out items).
- **Reports**: revenue, average ticket, peak hours, best sellers and top customers, with CSV export.
- **Staff and roles**: owner, cashier and kitchen, each with its own access.
- **Server-rendered SEO**: title, description, Open Graph, favicon and JSON-LD (`Restaurant`) injected into the HTML on every request, plus dynamic `robots.txt` and `sitemap.xml`. On the static deployment the same logic runs in a Vercel Edge Middleware.
- **Getting-started guide**: side checklist that detects on its own what the owner has already set up.

## WhatsApp: Two Providers per Store

- **Meta Cloud API (official)**: guided connection with just the token, phone number discovery, automatic creation of message templates and webhook registration. Order status notifications with editable texts and an attendant with predefined replies (keywords, after hours, welcome, handoff to a human), with `X-Hub-Signature-256` signature verification.
- **QR Code (worker)**: always-on Node service (Baileys) with one connection per store, sessions encrypted with AES-256-GCM in Postgres, a lease to prevent two instances from using the same session, and send limits to protect the number.

## Platform (Superadmin)

Platform panel with MRR, store management, plans with product, table and user limits, free trial with activation tracking ("at risk: call the owner"), billing with grace period and automatic suspension, Mercado Pago integration, per-store WhatsApp health, audit log and an "enter as the store" support mode.

## Tech Stack

- **Front-end**: React 18, Vite, React Router, Chart.js, HugeIcons, model-viewer.
- **Back-end**: Node.js with Express in a monorepo using npm workspaces.
- **Data**: Postgres (Supabase compatible, with RLS) in production and JSON with atomic writes in development; photos on Vercel Blob named by content hash.
- **Notifications**: Web Push and WhatsApp (Cloud API and Baileys).
- **Infra**: Vercel (client and server), Docker and Caddy for the worker, CI running tests and build on every push and pull request.

## Security

Orders validated and totals computed on the server, image uploads with content checks (SVG rejected), signed session tokens, encrypted credentials and tokens, login rate limiting with lockout, and a public API that never exposes tokens, secrets or orders.
